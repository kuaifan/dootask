# 无法在线更新系统或更新失败怎么办

## 问题
管理员在「设置 → 系统更新」页看到不支持在线更新的提示，或者更新过程中显示「系统更新失败」。

## 原因
- 「在线更新已关闭」：运维在服务器 `.env` 中设置了 `ONLINE_UPDATE=false`
- 「当前部署方式不支持在线更新」：代码目录不是 Git 仓库（例如手动上传的代码包）
- 「当前代码不在任何分支上」：服务器代码处于游离状态（detached HEAD）
- 「无法连接代码仓库」：服务器无法访问代码仓库，或仓库地址需要账号密码 / SSH 密钥
- 「应用商店服务版本过低」：旧版本首次使用，内置的应用商店服务还没有在线更新能力
- 「服务器存在本地修改」：服务器上有人改过代码且未提交，在线更新不会覆盖这些修改
- 更新中途失败：常见于网络中断、依赖安装失败、数据库迁移失败

## 解决
- 以上不支持的情况：请运维在服务器项目目录执行 `./cmd update` 更新；「应用商店服务版本过低」只需手动执行一次，之后即可在线更新
- 本地修改：运维确认这些修改是否需要保留，处理后再更新
- 更新失败：页面会显示失败原因、日志和更新前的数据库备份文件；运维可根据日志处理后重新执行 `./cmd update`，必要时用 `git reset --hard <更新前的提交>` 回滚代码、用 `./cmd mysql recovery` 还原数据库
- 「重启服务」阶段暂时连不上服务器属正常，一般 1~3 分钟内恢复；长时间无法恢复请运维检查容器状态
